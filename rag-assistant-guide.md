# Как работает RAG-ассистент

Практическая инструкция для проекта `5-8`. Объяснения относятся к варианту OpenAI в папке `assistant_api` и к коду, рассмотренному при подготовке инструкции.

## 1. Для чего нужен проект

Ты задаёшь вопрос, а ассистент ищет информацию в твоих материалах и составляет по ней ответ.

Представь сотрудницу с инструкцией:

1. Она получает вопрос.
2. Находит нужные страницы инструкции.
3. Читает их и формулирует ответ.
4. Записывает ответ, чтобы при повторном вопросе быстро его вернуть.

Этот подход называется **RAG**: сначала программа находит сведения в документах, затем передаёт их языковой модели вместе с вопросом.

## 2. Что для чего предназначено

Все пути ниже указаны относительно корня проекта `5-8`.

- **`assistant_api/data/docs.txt`**: исходная база знаний, обычный текстовый документ. Здесь ты хранишь сведения для ответов.
- **`assistant_api/chroma_db/`**: поисковая база ChromaDB. Хранит фрагменты документа и их числовые представления для поиска по смыслу.
- **`assistant_api/api_rag_cache.db`**: кеш SQLite. Хранит уже полученные ответы вместе с вопросами, использованным контекстом и временем записи.
- **`assistant_api/app.py`**: запускает общение с ассистентом в терминале.
- **`assistant_api/rag_pipeline.py`**: управляет последовательностью обработки вопроса: кеш, поиск, запрос к модели, сохранение ответа.
- **`assistant_api/vector_store.py`**: читает исходный документ, готовит фрагменты, загружает их в ChromaDB и выполняет поиск.
- **`assistant_api/cache.py`**: читает и сохраняет готовые ответы в SQLite.
- **`assistant_api/evaluate_ragas.py`**: запускает автоматическую оценку качества поиска и ответов.
- **`.env`**: хранит локальные настройки доступа к API. Значения ключей не нужно отправлять в чат или публиковать.
- **`venv_py311/`**: отдельное окружение Python с библиотеками проекта.

Папка `assistant_giga` содержит отдельный вариант ассистента с GigaChat. Для запуска варианта OpenAI она не нужна.

## 3. Как данные попадают в ChromaDB

**Загрузка происходит при запуске ассистента, до первого вопроса, если используемая коллекция ChromaDB пустая.** Коллекция похожа на отдельный раздел базы данных. В этом варианте используется `api_rag_collection`.

После запуска `app.py` программа:

1. Открывает ChromaDB и проверяет количество записей в коллекции.
2. Если коллекция пустая, читает `data/docs.txt`.
3. Разбивает текст на фрагменты, которые в коде называются чанками. Целевой размер около 500 символов; соседние фрагменты частично перекрываются, чтобы сохранить контекст. Фактический размер может отличаться.
4. Отправляет каждый фрагмент в OpenAI для создания **embedding**.
5. Сохраняет в ChromaDB и текст фрагмента, и его embedding.

Embedding можно представить как числовой «адрес смысла» текста. Он помогает находить близкие по смыслу фразы, даже когда слова не совпадают. Например, вопрос «Как компьютер учится на примерах?» может привести к фрагменту про машинное обучение.

Это подготовка документа для поиска. Сама языковая модель на твоём документе здесь не обучается.

При следующем запуске программа использует сохранённую коллекцию повторно.

> В текущем коде изменение `docs.txt` не вызывает обновление ChromaDB. Программа проверяет только наличие записей в коллекции, а не изменения исходного файла.

## 4. Что происходит при вопросе

Допустим, ты ввела: «Что такое нейронная сеть?»

Сначала программа проверяет кеш SQLite.

Если такой вопрос уже есть, она возвращает сохранённый ответ. Поиск в ChromaDB и генерация нового ответа пропускаются. При сравнении вопросов не учитываются регистр и лишние пробелы. Переформулировки по смыслу кеш не распознаёт.

Если ответа в кеше нет:

1. Вопрос отправляется в OpenAI и превращается в embedding.
2. ChromaDB ищет три наиболее близких по смыслу фрагмента из сохранённой базы.
3. Программа составляет промпт: вопрос, найденные фрагменты и инструкции для модели. Промпт здесь означает текст задания модели.
4. Модель составляет ответ. В инструкции ей задано отвечать по предоставленным фрагментам и сообщать, если информации недостаточно. Соблюдение этой инструкции нужно проверять.
5. Программа показывает ответ в терминале.
6. Вопрос, ответ и использованные фрагменты сохраняются в кеше.

В проекте у OpenAI две разные роли:

- **`text-embedding-3-small`** создаёт числовые представления фрагментов и вопросов для поиска.
- **`gpt-4o-mini`** составляет ответ по найденным фрагментам.

При обработке нового вопроса модели для ответа передаются найденные фрагменты. Весь исходный документ при каждом вопросе не отправляется.

ChromaDB и SQLite хранятся локально. Но создание embeddings, генерация ответов и оценка через OpenAI требуют доступа к API и расходуют баланс. При первоначальной подготовке базы текстовые фрагменты отправляются в OpenAI для создания embeddings.

## 5. Чем ChromaDB отличается от кеша SQLite

Это два отдельных хранилища с разными задачами:

- **ChromaDB**: «Вот материалы, среди которых нужно найти сведения для нового ответа».
- **SQLite**: «На этот вопрос мы уже отвечали, вот готовый ответ».

Команда `clear` внутри ассистента очищает записи кеша в `api_rag_cache.db`. Сам файл остаётся. Исходный `docs.txt` и содержимое ChromaDB эта команда не меняет.

Пример со сменой данных:

1. В `docs.txt` написано: «Гарантия составляет 1 год».
2. При первой загрузке этот текст попал в ChromaDB.
3. Ты спросила про гарантию. Ответ «1 год» сохранился в SQLite.
4. Ты изменила `docs.txt`: теперь гарантия 2 года.
5. Выполнила `clear`.

Готового ответа в SQLite больше нет, но в ChromaDB остался старый текст про 1 год. При новом вопросе ассистент может снова ответить по старой информации.

**После изменения базы знаний нужно обновить ChromaDB и очистить кеш SQLite.** Очистки одного кеша недостаточно.

## 6. Как запустить ассистента

Предполагается, что окружение Python и зависимости уже установлены, а `OPENAI_API_KEY` указан в корневом `.env`. Подготовка окружения описана в [Readme.md](Readme.md).

Если терминал открыт в корне проекта `5-8`, выполни:

```powershell
cd .\assistant_api
..\venv_py311\Scripts\python.exe .\app.py
```

Если терминал уже находится в `assistant_api`, выполняй только вторую команду.

После сообщения о готовности вводи вопросы в терминале.

Команды внутри запущенного ассистента:

- `stats`: показать статистику поисковой базы и кеша.
- `clear`: очистить кеш ответов после подтверждения.
- `exit`, `quit` или `q`: завершить работу.

Эти команды вводятся в приглашении ассистента, а не в PowerShell после его завершения.

> Пути к `data/docs.txt`, `chroma_db` и файлу кеша в коде относительные. Запускай программу из `assistant_api`, как указано выше. Запуск из другой папки может привести к поиску исходного файла или созданию хранилищ в другом месте.

## 7. Как обновить ChromaDB после изменения документа

Отдельной команды обновления в текущем проекте нет. Можно сохранить старую ChromaDB под другим именем. При следующем запуске ассистент создаст новую из актуального документа.

1. Заверши ассистента командой `exit`. Если запущен скрипт оценки, дождись его завершения или останови его.
2. Отредактируй и сохрани `assistant_api/data/docs.txt`.
3. В PowerShell, находясь в папке `assistant_api`, переименуй старую поисковую базу:

   ```powershell
   Rename-Item -LiteralPath .\chroma_db -NewName chroma_db_backup
   ```

   Команда применима, если `chroma_db` существует. Если базы ещё нет, переименование не требуется. Если имя `chroma_db_backup` уже занято, используй свободное имя, например `chroma_db_backup_2`. Резервную копию не нужно перезаписывать.

4. Запусти ассистента:

   ```powershell
   ..\venv_py311\Scripts\python.exe .\app.py
   ```

5. Дождись создания новой поисковой базы и сообщения о готовности. Создание embeddings потребует запросов к OpenAI API.
6. Внутри ассистента введи `clear` и подтверди очистку, чтобы убрать ответы по старому документу.
7. Задай вопрос об изменённых сведениях и сравни ответ с актуальным `docs.txt`.

Старая ChromaDB останется в переименованной папке как резервная копия. Исходный документ при пересоздании базы не удаляется.

## 8. Как добавить новый источник данных

Сейчас программа читает только `assistant_api/data/docs.txt`. Если положить рядом второй файл, он автоматически не загрузится.

### Вариант, который работает без изменения кода

1. Добавь текст нового источника в конец `docs.txt`, сохранив прежние материалы.
2. Сохрани файл.
3. Пересоздай ChromaDB по инструкции из раздела 7.
4. Очисти старые ответы командой `clear` внутри ассистента.

В новую поисковую базу попадёт весь актуальный текст документа: прежние сведения и добавленные материалы.

### Отдельные файлы для разных источников

Можно было бы хранить материалы так:

```text
data/
  machine-learning.txt
  neural-networks.txt
  company-rules.txt
```

**Такой режим пока не реализован.** Для него нужно доработать загрузчик, чтобы он:

- читал несколько поддерживаемых файлов;
- разбивал их на фрагменты и добавлял в ChromaDB;
- сохранял имя источника у каждого фрагмента;
- отличал новые и изменённые файлы от уже загруженных, чтобы избегать дублей и устаревших записей.

PDF, Word и ссылки также потребуют отдельной обработки. Текущий загрузчик рассчитан на обычный текстовый файл.

## 9. Для чего нужен RAGAS

**RAGAS помогает автоматически оценивать качество поиска и ответов ассистента.** Для обычного общения его запускать не нужно. Он нужен при проверке качества и сравнении изменений.

В текущем скрипте используются две метрики:

- **Faithfulness, соответствие источнику**: подтверждаются ли утверждения ответа найденными фрагментами? Не добавила ли модель неподтверждённые сведения? Высокая оценка не гарантирует истинность самого исходного документа. [Описание метрики](https://github.com/vibrantlabsai/ragas/blob/main/docs/concepts/metrics/available_metrics/faithfulness.md).
- **Context Precision, качество найденного контекста**: насколько полезны найденные фрагменты и находятся ли полезные фрагменты выше в результатах поиска? Используемый вариант требует эталонного ответа. [Описание метрики](https://github.com/vibrantlabsai/ragas/blob/main/docs/concepts/metrics/available_metrics/context_precision.md).

Контекст здесь означает фрагменты документа, переданные модели для ответа.

Например, поиск может найти нужные фрагменты, но модель добавит выдуманные сведения. Это проблема формирования ответа. Или поиск вернёт материалы на другую тему. Это проблема поиска.

RAGAS помогает оценить эти стороны работы, но не заменяет проверку всей программы: команд терминала, сохранения данных и других пользовательских сценариев.

## 10. Как устроен запуск оценки

Скрипт `evaluate_ragas.py` самостоятельно:

1. Создаёт ту же систему поиска и ответов, которую использует `app.py`.
2. Открывает коллекцию ChromaDB. Если она пустая, загружает `docs.txt`.
3. Задаёт пять вопросов из списка `EVALUATION_QUESTIONS`.
4. Получает новые ответы без чтения и записи кеша: используется `use_cache=False`.
5. Собирает вопросы, ответы, найденные фрагменты и данные для сравнения.
6. Запускает оценку RAGAS с обращениями к OpenAI.
7. Выводит результаты по вопросам и средние оценки в терминал.

Одновременно запускать `app.py` не требуется. Скрипт оценки сам вызывает нужную логику. В текущем коде отдельный файл отчёта не сохраняется.

Для запуска из папки `assistant_api`:

```powershell
..\venv_py311\Scripts\python.exe .\evaluate_ragas.py
```

Если терминал находится в корне `5-8`, сначала выполни:

```powershell
cd .\assistant_api
```

Подробности окружения и зависимостей: [ragas-setup-guide.md](ragas-setup-guide.md).

Оценка расходует баланс OpenAI API: запросы нужны и для получения ответов ассистента, и для их проверки.

## 11. Ограничения текущей оценки

В скрипте используется учебное упрощение. Вместо независимого правильного ответа берутся первые 100 символов ответа самого ассистента:

```python
ground_truths_list.append(result["answer"][:100])
```

Получается, что ответ ассистента частично используется как эталон для проверки поиска. Такая проверка не даёт надёжной независимой оценки.

Для содержательной оценки нужно подготовить вопросы по базе знаний и правильные ответы, проверенные по исходным материалам. При смене темы `docs.txt` текущие пять вопросов тоже нужно пересмотреть.

Отдельно полезно проверить вопросы, ответа на которые нет в базе. Ожидаемое поведение: ассистент сообщает о недостатке информации. Не все метрики для обычных вопросов подходят для оценки такого отказа, поэтому эти случаи нужно проверять отдельно.

Надписи «Отличное качество» и пороги баллов в скрипте заданы автором проекта. Они не являются универсальными критериями готовности. Среднее двух метрик также не заменяет анализ отдельных ответов.

Если метрика не вычислилась, это не равно нулевому качеству ответа. Текущий скрипт исключает `NaN` при подсчёте средних, а если допустимых значений нет, подставляет `0`. Поэтому нужно смотреть и подробные результаты, и сообщения об ошибках.

## 12. Рекомендуемый порядок работы

1. **Подготовить исходные сведения.** Проверить содержимое `assistant_api/data/docs.txt`.
2. **Подготовить поисковую базу.** При первом запуске она создастся автоматически. После изменения документа её нужно обновить по разделу 7 и очистить кеш.
3. **Проверить ассистента вручную.** Задать несколько вопросов по документу и вопрос, ответа на который в документе нет. Сравнить ответы с источником.
4. **Подготовить проверочные вопросы и эталоны.** Заменить учебную заглушку в оценке независимыми правильными ответами. В текущем проекте это потребует доработки скрипта.
5. **Запустить RAGAS.** Изучить отдельные ответы и метрики, а не только общий балл.
6. **Повторять оценку после изменений.** Для сравнения использовать один и тот же набор вопросов и эталонов. Если изменился сам источник, эталоны тоже нужно проверить и актуализировать.

Для обычного общения достаточно `app.py`. Для оценки качества используется `evaluate_ragas.py`. После изменения исходного документа нужно обновить поисковую базу, иначе и общение, и оценка могут использовать старые сведения.

## Основание инструкции

Материал собран из объяснений по проекту и рассмотренной логики кода. Создание этого документа не включает запуск генерации ответов, пересоздание ChromaDB или выполнение RAGAS. Эти действия выполняются отдельно по приведённым инструкциям.
