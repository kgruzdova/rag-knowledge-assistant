# RAG-ассистент: OpenAI и GigaChat

Учебный консольный проект на Python для ответов на вопросы по текстовой базе знаний. Доступны два отдельных режима: OpenAI и GigaChat. Для режима OpenAI есть скрипт оценки качества через RAGAS.

RAG (Retrieval-Augmented Generation) дополняет запрос к языковой модели фрагментами из документов. В этом проекте документы хранятся в `data/docs.txt`, поиск выполняется через ChromaDB, ответы сохраняются в локальный кеш SQLite.

## Как работает ассистент

1. Проверяет, есть ли ответ на вопрос в кеше.
2. Если ответа нет, отправляет вопрос в API для создания числового представления, embedding.
3. Находит три близких по смыслу фрагмента в ChromaDB.
4. Передаёт вопрос и найденные фрагменты языковой модели.
5. Выводит ответ и сохраняет его в кеше.

В режиме OpenAI используются `gpt-4o-mini` для ответов и `text-embedding-3-small` для embeddings. В режиме GigaChat в коде заданы модели `GigaChat` и `Embeddings`.

Для работы без кешированного ответа нужны интернет, доступ к API выбранного сервиса и соответствующие учётные данные. Текст вопроса и найденные фрагменты передаются внешнему провайдеру. Во время первичной загрузки документов их фрагменты также отправляются для создания embeddings. Запросы могут расходовать баланс API.

## Подготовка окружения

Команды ниже предназначены для Windows PowerShell. Вводите их по одной, нажимая Enter после каждой.

Перейдите в корень проекта:


Если `venv_py311` уже подготовлено, достаточно активировать его:

```powershell
.\venv_py311\Scripts\Activate.ps1
```

Для установки с нуля нужен установленный Python 3.11. Создавайте окружение только при его отсутствии:

```powershell
py -3.11 -m venv venv_py311
.\venv_py311\Scripts\python.exe -m pip install --upgrade pip
.\venv_py311\Scripts\python.exe -m pip install -r requirements-py311-lock.txt
```

Файл `requirements-py311-lock.txt` фиксирует полный проверенный набор версий. Альтернатива для установки по основным зависимостям:

```powershell
.\venv_py311\Scripts\python.exe -m pip install -r requirements.txt
```

В набор входят PyTorch и библиотеки обработки данных, поэтому первая установка может занять заметное время и место на диске.

## Настройка API

Создайте `.env` в корне `5-8`, рядом с `requirements.txt`.

Для режима OpenAI и оценки RAGAS:

```dotenv
OPENAI_API_KEY=your-openai-api-key
```

Для режима GigaChat:

```dotenv
GIGACHAT_AUTH_KEY=your-gigachat-authorization-key
GIGACHAT_RQUID=your-request-uuid
```

Укажите собственные значения вместо примеров. `GIGACHAT_AUTH_KEY` в текущем клиенте используется как ключ Basic-авторизации, `GIGACHAT_RQUID` как идентификатор запроса. OAuth scope в коде: `GIGACHAT_API_PERS`.

Если используете оба режима, переменные можно хранить в одном `.env`. Не публикуйте этот файл и не отправляйте значения ключей в чат. Перед добавлением проекта в Git исключите `.env`, виртуальные окружения и локальные базы данных из отслеживания.

## Запуск OpenAI-ассистента

Из любого текущего расположения в терминале:

```powershell
..\venv_py311\Scripts\python.exe .\app.py
```

Явный путь к Python выбирает нужное окружение, даже если в приглашении терминала отображается другое.

После сообщения о готовности введите вопрос, например: `Что такое машинное обучение?` Ответ зависит от содержимого базы знаний.

Команды внутри приложения:

- `stats`: статистика векторного хранилища и кеша.
- `clear`: очистка кеша ответов после подтверждения. Документы в ChromaDB эта команда не удаляет.
- `exit`, `quit` или `q`: завершение работы.
- `Ctrl+C`: прерывание выполнения.

## Оценка через RAGAS

```powershell
..\venv_py311\Scripts\python.exe .\evaluate_ragas.py
```

Скрипт получает ответы на пять заданных в коде вопросов без использования кеша, затем рассчитывает:

- **Faithfulness**: насколько утверждения ответа подтверждаются предоставленным контекстом.
- **Context Precision**: качество порядка найденных фрагментов относительно эталонного ответа.

Скрипт выводит значения по каждому вопросу и средние показатели. Оценка тоже обращается к OpenAI API и расходует баланс. Модель генерации ответов явно задана как `gpt-4o-mini`; модель оценщика отдельно не настроена и выбирается фабрикой RAGAS.

**Ограничение оценки:** сейчас `ground_truth` формируется из первых 100 символов ответа самой модели. Это демонстрационный вариант, а не независимый эталон. Для содержательной проверки качества нужны вручную подготовленные правильные ответы. Итоговый средний балл и текстовые категории в скрипте не являются подтверждённой оценкой качества продукта.

Подробности настройки: [ragas-setup-guide.md](ragas-setup-guide.md).

## Документы и сохранение данных

Для каждого режима используется собственный файл `data/docs.txt` в кодировке UTF-8. При первом запуске текст разбивается на фрагменты и загружается в пустую коллекцию ChromaDB.

Данные сохраняются в папке запускаемого режима:

- `chroma_db/`: векторное хранилище.
- `api_rag_cache.db`: кеш ответов режима OpenAI.
- `gigachat_rag_cache.db`: кеш ответов режима GigaChat.

При следующих запусках существующие данные используются повторно. Число «Документов» в выводе коллекции соответствует сохранённым фрагментам.

Изменение `data/docs.txt` не обновляет уже заполненную коллекцию автоматически. Для новой базы знаний нужна отдельная переиндексация; готовой команды для неё в интерфейсе нет. Очистка кеша через `clear` не выполняет переиндексацию. Перед изменением или сбросом хранилища сохраните копию данных.

## Частые ошибки

### Python не находит файл

Проверьте текущую папку командой `Get-Location`. Файлы `app.py` и `evaluate_ragas.py` режима OpenAI находятся в `assistant_api`, а не в корне проекта. Переходите в папку режима перед запуском, поскольку пути к документам и базам относительные.

### `No module named 'dotenv'`

Обычно выбран Python из другого окружения или зависимости ещё не установлены. Используйте явный путь `..\venv_py311\Scripts\python.exe` из папки режима. Установку зависимостей выполняйте из корня проекта.

### `No module named 'langchain_community.chat_models.vertexai'`

RAGAS в этом проекте использует старый путь импорта, отсутствующий в `langchain-community 0.4.2`. Не обновляйте пакеты LangChain по одному: установите согласованный набор из `requirements-py311-lock.txt` в основное окружение.

### PyArrow требует NumPy 2

Для выбранной ветки LangChain используется NumPy 1.26.4. В зависимостях закреплены совместимые `datasets==3.6.0` и `pyarrow==20.0.0`. Восстановите набор зависимостей из файлов проекта.

### Долго отображается «Поиск релевантных документов через API»

До локального поиска выполняется сетевой запрос для embedding вопроса. Задержка может быть связана с API, соединением или повторными попытками SDK. Сам факт вывода этой строки не позволяет определить точную причину. Можно прервать запуск через `Ctrl+C`; если появится ошибка, сохраните её текст без ключей.

В текущем коде собственные короткие тайм-ауты для OpenAI не заданы. Обычная инициализация клиента не подтверждает работоспособность ключа или наличие баланса.

## Ограничения текущей реализации

- Это локальное консольное приложение. Веб-интерфейса и общей базы пользователей нет.
- Работа с API и полноценная оценка требуют отдельной проверки с действующими учётными данными.
- В клиенте GigaChat запросы выполняются с `verify=False`, то есть проверка TLS-сертификатов отключена, а явные тайм-ауты не заданы. Перед использованием с реальными конфиденциальными данными нужно настроить проверку сертификатов и ограничения ожидания.
- Существующий код использует старую ветку LangChain. Переход на новые основные версии требует проверки совместимости, а не только обновления списка пакетов.
